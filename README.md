# Campus Tester

Локальная система запуска браузерных тестов публичного сайта через Jenkins.

На текущем этапе реализована проверка доступности сайта в Chromium. Jenkins загружает `Jenkinsfile` из Git-репозитория и запускает Playwright в официальном Docker-образе.

## Требования

- Git;
- Docker с поддержкой Docker Compose;
- свободный порт `8080`.

## Запуск

```bash
git clone https://github.com/eldar-safin/campus-tester.git
cd campus-tester
```

На Linux и macOS:

```bash
./start.sh
```

На Windows:

```bat
.\start.bat
```

Скрипт для вашей операционной системы соберёт и запустит контейнеры, дождётся готовности Jenkins и выведет адрес веб-панели. Эквивалентный запуск напрямую через Docker Compose:

```bash
docker compose up -d --build --wait
```

По умолчанию адрес сайта не задан: Jenkins запросит его перед запуском теста. Чтобы задать адрес заранее, создайте локальный `.env`:

```bash
cp .env.example .env
```

Укажите в нём абсолютный HTTP- или HTTPS-адрес:

```dotenv
TARGET_URL=https://example.ru
```

Файл `.env` исключён из Git.

## Вход в Jenkins

Откройте [http://localhost:8080](http://localhost:8080) и войдите с учётными данными из `.env`. Значения по умолчанию:

```text
Логин: admin
Пароль: admin
```

Пользователь, плагины и Pipeline создаются автоматически. Мастер первоначальной настройки Jenkins отключён.

Без авторизации можно открыть задание, запустить его и посмотреть результаты. Учётная запись администратора требуется только для изменения заданий и системных настроек Jenkins.

Пароль `admin` предназначен только для локального запуска. По умолчанию порт Jenkins привязан к `127.0.0.1`, но пароль всё равно рекомендуется изменить в `.env`:

```dotenv
JENKINS_ADMIN_PASSWORD=надёжный-пароль
```

Пароль управляется через `.env`: изменение только через Jenkins UI может быть перезаписано конфигурацией JCasC после перезапуска контейнера.

Данные Jenkins находятся в именованном Docker volume и сохраняются после перезапуска или `docker compose down`.

## Pipeline

При запуске Jenkins автоматически создаётся задание `campus-tester`. Его конфигурация описана в `jenkins/jenkins.yaml` и использует следующие переменные:

- `JENKINSFILE_REPOSITORY` — адрес Git-репозитория;
- `JENKINSFILE_BRANCH` — ветка без префикса `refs/heads/`;
- `JENKINSFILE_PATH` — путь к Jenkinsfile внутри репозитория.

Значения по умолчанию заданы в Docker Compose: текущий репозиторий, ветка `main` и путь `Jenkinsfile`. Для разработки локальный `.env` может переопределить ветку:

```dotenv
JENKINSFILE_BRANCH=dev
```

Если `TARGET_URL` не задан в `.env`, Pipeline остановится на стадии **Подготовка** и запросит адрес сайта.

## Ручной запуск Playwright

При заполненном `TARGET_URL` в `.env` тест можно запустить без Jenkins:

```bash
docker compose --profile tests run --rm playwright
```

## Остановка

```bash
docker compose down
```

Эта команда не удаляет данные Jenkins.

## Безопасность

- не добавляйте `.env`, пароли и другие секреты в Git;
- смените стандартный пароль `admin`, если меняете локальную привязку порта Jenkins;
- Jenkins имеет доступ к Docker socket и фактически может управлять Docker на хосте;
- запускайте только доверенный `Jenkinsfile` и не публикуйте этот Jenkins в Интернет без отдельной настройки безопасности.

## Текущие ограничения

- используется только Chromium;
- реализована только проверка доступности сайта.
